# 见趣 · 闺蜜机 / OpenDesign 初稿改造 V0.2

> 设计演示，不是可交付业务系统。基于用户提供的「闺蜜机首轮视觉探索.zip」修改，未重建一套管理后台。

## 打开方式

- `index.html`：大型 Android 横屏的 A「日光客厅」/ B「暖夜剧场」设计探索。右下角灰蓝色小球是**仅供设计评审**的模式与页面切换工具，并非产品 UI。
- `mobile.html`：轻量的自有手机 H5 接力概念；宽度 ≤700px 打开 index.html 时自动进入此页面，可通过链接返回大屏评审画布。
- 两个页面均使用本地相对资源，在 Chrome 等现代浏览器中直接打开即可，无须 npm 安装。实机兼容性、Android WebView 适配和离线性能仍待测。

## 本轮保留和改进

- **保留**原始 A/B 视觉方向和五个主要画面：个人首页、视频观看、AI 助手、数字人课程、公共服务；保留本地图片素材、版权署名与原版样式（`assets/app.css`）。
- **品牌**替换为暂定名称「见趣」，闺蜜机是产品类型；所有页面增加清晰的“概念演示，非真实服务”标识。
- **实际可操作的设计流程**：入口 → 商城商品 → 商家、运费与订单核对 → 模拟确认；活动详情 → 大屏报名确认 → 模拟结果；AI 人格选择；搜索和 AI 趣玩流程说明。
- **纠正虚假成功**：原稿点击“报名”瞬间显示“已报名”，现禁止该行为；不生成真实订单、活动回执，也不声称语音输入、数字人声音、视频、创作模型已接入。
- **修正示例素材**：AI 购物卡不再用客厅室内照片假冒血压计照片，改为洗衣液符号化占位；删除无凭据“步行 8 分钟”的声明。
- **独立手机陪伴**：不机械缩放大屏，保留随身需要的续播接力、活动、作品与个人权益；不依赖微信作为平台身份。

## 本次不宣称完成

1. **未接任何真实数据或业务接口**：商品、日期、商家、价格、活动、人物和剧目只是样例；无支付、报名核销、作品上传或长记忆。
2. **AI/数字人**：课程的角色切换仍是视觉概念，不会播放不同声线；原对话是预设样例，未接 STT/TTS 或 Agent 工具调用。
3. **视频**：播放器当前是静态场景，无已授权视频流、续播账号同步和 DRM；示例短剧名称不是已经采购的内容。
4. **主大屏版仍以 1920×1080 横屏评审画布为中心**，没有真正通过 21.5—32 英寸实机兼容验证；**大尺寸竖屏是明确待办**。不能把 CSS 缩放宣称为可用的横竖双适配。
5. **内容版权**：沿用原始 CREDITS 中的开放授权素材，但用于商业公开展示前必须逐张核验署名和衍生授权；不能把纪录照片当成真实剧照/产品摄影。

## 下一轮

先让产品负责人比较 A/B 的视觉气质，并检验新增流程是否自然。选定方向后再做大屏真实响应式布局、画面比例和角色设计；依授权确定短剧内容和 AI API PoC，之后才进入产品工程化。

**变更原则**：只提交 PR，不直接合并进 main；不触碰 `base-prototype` 或发布工作流，等待产品负责人视觉验收。
