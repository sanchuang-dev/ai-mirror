# 闺蜜机｜产品功能设计 V0.1

> 日期：2026-10-15 · 归属：AI 镜面产业五端产品 · 状态：**功能基线草案（未经最终设计验收）**  
> 用途：指导两周展厅原型的信息架构、交互稿、AI PoC 与商务演示。不是量产 PRD、硬件验收报告或已交付清单。

## 0. 阅读规则：别把推论当决策

- **[已确认]**：产品负责人在讨论中明确选择/确认。
- **[设计建议]**：为落实目标提出，需在交互设计时确认。
- **[待验证]**：供应商能力、硬件参数、内容/支付合规、用户数据或技术可行性尚无实测证据。
- **[演示]**：两周可点击可讲述的原型，不自动等于可上线能力。

## 1. 产品定义与边界

**[已确认] 一句话**：闺蜜机是一款以个人长期使用为主的大型 Android 平板式 AI 生活娱乐与服务终端；免费内容培养使用习惯，AI 伙伴/创作提升体验，熟人关系与作品承载用户价值，自有会员、商城、广告和第三方服务实现商业化。

**不是**：养老院内部管理系统、微信小程序的放大版、强制聊天的 AI 客服、仅供大堂围观的数字人展品，或完全依靠 AI Token 售卖的产品。

| 产品维度 | 已确定决策 |
| --- | --- |
| 设备与渠道 | 大型 Android 平板，不是镜子；个人购买、机构采购、渠道投放并存 |
| 使用方式 | **个人使用为主**，能连续娱乐约半小时；大堂/活动中心另设公共服务与演示模式 |
| 核心入口 | 内容与服务首页 + 可随时唤起的 AI 伙伴，**双入口** |
| 日常内容 | 合法授权的免费短剧、戏曲、老歌、新闻、广场舞、健康科普；适量且透明的商业内容 |
| AI 创作 | 重点覆盖当下才艺/形象趣玩，也兼顾口述往事；兴趣而非性别决定功能 |
| 社交 | 身边熟人及兴趣关系优先；不围绕养老院边界构建封闭圈子 |
| 线下供给 | 网格位置 + 个人兴趣分发；商家、场地方提供内容，平台审核与运营 |
| 商城 | 供应商**在我们的商城开店**，平台提供下单与会员权益，供应商履约 |
| 私人 AI | 长期固定人格 + 可切换 RP 角色；可以自选形象/声线与适度讲解风格 |
| 人格交互 | **不主动发起闲聊**；点击或可选语音唤醒；轻任务浮层、深度任务沉浸 |
| AI 办事 | 可检索商品、比较方案、组织订单、查活动和代填报名；付款/报名等外部动作在人确认后执行 |
| 私人隐私 | 分层长期记忆；**即使由子女付会员费，子女也只能看老人主动分享的内容** |
| 微信关系 | 可选分享/登录渠道，**不得以微信 OpenID 或小程序作为唯一平台身份与体验载体** |

**[待验证] 尺寸**：历史方案提及 21.5—32 英寸及竖屏展示，现阶段仅作设计约束候选。实际设备的尺寸、分辨率、横竖屏、摄像头、音视频、麦克风与性能以到货样机和厂家资料为准；不能直接把“27 英寸竖屏”写成已采购型号。

## 2. 用户与运行场景

| 角色 | 使用目的 | 关键能力/边界 |
| --- | --- | --- |
| 老人 / 个人用户 | 消磨半小时、追剧、听新闻、看健康科普、与熟人互动、AI 创作、购物 | 自己的内容、订单、作品、人格及记忆；独立控制是否分享 |
| 子女 / 家庭成员 | 欣赏主动分享的作品、点评、帮忙购买服务、购买会员 | **不能查看私人聊天、记忆和未经分享的活动轨迹**；代付不获得隐私读取权 |
| 场地方 | 在网格内提供活动与权益、承接体验 | 提交内容、核销和查看必要的本场地运营信息；不进入养老院床位/护理/排班系统 |
| 入驻商家 / 服务商 | 提供商品、课程、制作、生活服务、履约 | 在平台开店、上架、处理授权订单、售后；不能接触人格敏感记忆 |
| 平台运营 | 内容审核、网格配置、会员/权益、商家治理、推广 | 不提供随意阅读用户私人会话的运营后台 |

### 2.1 两种终端模式

**个人模式 [已确认]**：已识别/登录的个人设备，可记住追剧进度、兴趣、作品、授权记忆、订单与会员状态。个人化的 AI 伙伴可被主动召唤，支持 RP、语音和服务执行。

**公共服务/演示模式 [已确认]**：默认展示当前位置附近的活动、内容、福利与商城服务；不加载私人长期记忆、亲密角色或他人的订单。允许游客先试用、再扫码保存成果；涉个人信息时采用一次性会话并自动清理。

**[设计建议]** 机构采购设备不自动等于公共设备：通过设备部署配置决定“个人专用”或“公共共享”，不是由购买方身份决定。

### 2.2 账户和隐私

- **[已确认]** 平台独立账户；扫码可进入自有 H5/网页，不强依赖微信。公共模式游客可先看内容/体验部分功能。
- **[设计建议]** 登录采用手机号或可接入的第三方快捷登录；访客作品保存时再做身份衔接。实际注册/实名要求依服务类型进一步确认。
- **[设计建议]** 个人记忆、订单、浏览历史、相册均隔离到个人账户；公共会话有退出、超时、清屏、异常重启恢复机制。
- **[已确认]** 子女与机构不因付费或拥有设备获得私人会话访问权；仅在用户主动分享或履约所必需的范围内开放信息。

| 功能域 | 功能项 | 用户价值 | 两周优先级 |
| --- | --- | --- | --- |
| ① 乐龄剧场 | 免费短剧、续播、收藏、戏曲/老歌/新闻/视频、频道、内容搜索 | 半小时连续使用的主体 | **P0 完整主链** |

| ③ AI 创作 | 写真、美化形象、回忆录、书画展示、演唱/祝福、作品集 | 趣味、表达与被欣赏 | **P0 一条真实生成链** |
| ④ 活动与福利 | 网格活动列表、报名、签到/核销、福利券、优惠权益 | 线下到访与消费转化 | **P0 报名及领取演示** |
| ⑤ 商城与会员 | 多商家店铺、商品/服务、购物车、订单确认、会员权益、代付 | 主要商业承接 | **P0 商品到订单演示** |

| ⑦ 课程与健康生活 | 课程、数字人讲课、自选声线/形象、互动答疑、轻运动/科普 | 学习和生活服务 | **P0 数字人课程概念** |
| ⑧ 个人中心 | 追剧史、作品、兴趣、记忆控制、会员、订单、隐私与设备 | 可持续使用与自主控制 | P0 核心状态 |

**[设计建议] 首页原则**：第一屏同时存在“继续观看/推荐内容”“本地活动和权益”“随时可唤起 AI”；不因展示数字人而牺牲点选功能。个性化推荐仅在个人态生效，默认按网格分发公共内容。

## 4. 五条核心体验链（必须可独立讲清）

### F01｜娱乐 → 趣玩 → 交易（留存和带货）

1. 用户打开终端看到“继续看第 N 集”，进入合法授权的免费短剧播放。
2. 可连续播放、暂停、收藏、返回与下次续播；片前/集间允许少量清晰标识的广告，不采取暗扣费。
3. 用户自愿点击与剧情相关的“试试同款造型”或“附近主题活动”，进入 AI 写真、活动页或合作店铺。
4. 作品保存到用户作品集；商品由平台商城承接，订单信息由人确认。
5. 可观察指标：独立回访、平均有效观看时长、从内容到主动互动的比率、内容关联成交及净毛利。

**约束**：视频、剧照、人物、广告素材、同款商品均需相关授权；不得抓取其他平台内容直接商用；不设计不透明分集扣款。

### F02｜AI 购物（会办事，而不是会念广告）

> “给我找一款便宜点、送到家的洗衣液。”

1. 用户点击 AI 或主动语音唤醒。
2. AI 使用**平台商品目录**检索商品，按真实价格、规格、可送达区域、费用和商家资质筛选比较。
3. AI 以可核查的卡片展示 2—3 个方案，说明差异；用户点选/语音确认一个商品。
4. AI 可填写购物车与收货信息，但不得擅自支付；页面清晰列出订单金额、商家、配送和售后。
5. **下单/支付均需明确的人类确认**；缺货、越权、接口失败必须回退，不能虚构成功。

**商业底线**：广告商品必须标识推广属性，不能利用私密健康、家庭、财务或情绪记忆进行定向推销；“推荐”不等于用户授权购买。

### F03｜本地活动 + 福利（公私两端共用）

1. 游客看到本网格可报名的课程、健康讲座、兴趣活动以及明确标注领取条件的福利。
2. 允许**大屏报名**或扫码去自有网页报名，两种入口写入同一平台账户/记录。
3. 用户确认场次、位置、资格、个人信息使用及是否真实免费，再提交。
4. 展示报名凭证与领取/核销状态；由场地方/商家负责现场实际活动和实物履约。
5. 公共设备完成后清除个人信息；个人设备可保存活动日程。

**[待验证]** 实际库存、商家结算、核销接口与消息触达。演示可 Mock，但不能显示虚构的实际核销成功。

### F04｜AI 创作 → 老友欣赏 → 主动家庭分享

1. 老人选择 AI 写真/书法展示/唱歌作品/讲述往事中的一个主题。
2. 图片/文字/音频在授权后由 AI 处理；生成稿可重试、修改、否决，**本人确认后才保存与发布**。
3. 分享范围分为：仅自己、指定亲友/家人、公开作品展示；默认不公开。
4. 朋友可点赞、评论；子女**只能接收本人主动分享**的作品，可点评或购买授权的纪念相册/制作服务。
5. 入驻商家负责作品制作、物流及售后，平台负责订单与权益。

**[设计建议]** 个人作品集与隐私导出是留存资产，不可设置恶意退出障碍。

### F05｜数字人讲课 / RP（创新 PoC）

1. 老人选择同一节课程，例如《苏东坡与赤壁》。
2. 可选择讲师形象、合法授权的预设声线、语速与有限风格（通俗/严谨/幽默）。
3. **课程知识内容以供应商提供的审定资料为基础**；人格改变表现而不擅自改写事实和课程目标。
4. 支持暂停、简单语音提问、重复解释和返回课程；选择某角色进入独立 RP 体验。
5. RP 的虚构经历与人物关系**不能自动写入现实人生记忆**；用户能知道角色为 AI。

**[待验证]** 两周内优先做两种讲师声线的课程片段、切换和有限答疑；不承诺实时写实数字人全程无延迟、完整表情驱动和全课程自动重制。

## 5. AI 伙伴产品契约（公共服务 AI ≠ 私人闺蜜）

| 能力 | 公共服务模式 | 私人模式 |
| --- | --- | --- |
| 人格 | 通用、克制的服务助手 | 稳定私人角色 + 可切换 RP |
| 唤起 | 点击默认 | 点击 + 用户可启用语音唤醒 |
| 主动对话 | 不主动打招呼或推销 | **不主动发起聊天**，被唤起后可主动推进任务 |
| 记忆 | 会话任务状态，退出清除 | 兴趣/生活习惯的授权分层记忆；敏感信息更严格 |
| 显示 | 任务浮层，必要时切全屏 | 轻任务侧边浮层；聊天/课程/RP 全屏沉浸 |
| 执行能力 | 查活动、查服务、商品浏览，确认后报名 | 同上 + 个人授权下的收藏/购物车/订单操作 |
| 数据访问 | 不读取私人聊天及记忆 | 仅当前用户授权数据，不跨家庭共享 |
| 商业推荐 | 可标注广告和赞助 | 不把私人记忆用于隐性商业操纵 |

### 5.1 分层长期记忆（私人模式）

- **兴趣和偏好**：用户授权后可自动积累，如喜欢书法、粤曲、短剧类型。
- **操作记录**：追剧进度、预约与订单按业务事实保存，允许纠错。
- **人生档案/作品**：与用户确认过的真实经历、回忆录、图片、书画独立沉淀。
- **敏感信息**：健康、财务和家庭私事单独授权、用途最小化，不参加商品定向推销。
- **RP/虚构信息**：独立角色会话，不写回真实人生档案。
- **控制权**：查看、更正、删除、导出、关闭记忆；**平台不自动向子女生成私人对话报告**。

### 5.2 AI Agent 的行动边界

**[已确认]** AI 可以帮用户找商品、报名活动；支付、报名与其它有外部影响的动作必须人工确认。**[设计建议]** 操作遵循“理解意图 → 调用限定工具 → 结果预览 → 用户确认 → 执行 → 返回真实凭证”。不得因用户说“随便”就跳过扣款确认；不得用自然语言宣称未完成的预约已成功。

## 6. 长期留存设计：不能只靠签到鸡蛋

| 留存层 | 功能机制 | 应验证的行为 |
| --- | --- | --- |
| 内容习惯 | 免费短剧、戏曲、新闻、连续播放、收藏和续播 | 无福利情况下，用户是否主动回来 |
| 兴趣与自我表达 | AI 写真、书画展示、口述故事、数字人课程 | 用户是否反复创作/学习 |
| 熟人关系 | 老友点评、兴趣圈、共同活动、家庭主动分享 | 用户是否主动互动、邀请朋友 |
| 生活服务 | 网格活动、福利、可靠健康科普、商城、商品复购 | 用户是否真实报名、消费、复购 |
| 个人积累 | 作品集、人生档案、历史偏好与记忆 | 用户是否愿意持续管理个人内容 |

**商业逻辑 [已确认]**：免费看剧做基础权益，以明确广告、会员、商城交易及第三方服务赚钱；会员是 AI + 生活权益组合，而非仅卖 Token。适量广告允许，但要测试用户留存与利润之间的平衡。商家必须入驻我们自己的商城。

**[设计建议]** 指标优先关注 7/30 日复访、非福利主动访问、作品二次创作、朋友互动、报名/核销、真实订单毛利、AI 成本及广告引发的退出率。两周展厅只可观察首次体验和有限复访意愿，不宣称 30/90 日留存已成立。

## 7. 网格、商家和平台边界

- **网格 [已确认]**：设备有平台配置的服务网格；游客按网格看本地内容，个人登录后叠加兴趣与会员权益。网格不是养老院行政边界，也不是强制跨院社群。
- **供给 C 模式 [已确认]**：平台运营、入驻商家、场地方共同供给内容与活动；平台掌握审核、推荐、商家治理及权益规则。
- **交易 B+C [已确认]**：商家在自有商城开店，平台承接交易、会员和相关服务；外部服务商执行合法专业履约。责任划分需落实合同、售后及结算规则。
- **排除范围 [已确认]**：不建设养老院内部床位、护理、排班、内部收费等基建；不强制依赖微信或任一社交平台。
- **健康边界 [设计建议]**：健康讲座和科普内容必须可信，不提供诊断承诺，不以衰老、疾病恐惧促进高价消费，不把商品营销伪装成中立医疗建议。

## 8. 两周展厅原型的验收范围（10 个工作日上限）

**定义 P0 的原则**：至少一条真实 AI 调用链、一条娱乐到商业的链路、一条 AI Agent 执行预览链路、一条数字人课程体验；所有其它部分可以明确 Mock。五款终端仍属于整体计划，本文件只负责闺蜜机。

| 时间 | 闺蜜机工作结果 | 验收证据 |
| --- | --- | --- |
| D1—D2 | 用户故事、主页 IA、个人/公共模式、主流程低保真和样机参数复核 | 规格走查 + 实机尺寸/分辨率清单或待测声明 |
| D3—D4 | 短剧播放器续播 + 本地活动福利 + 商城商品/确认页 | 可点击无死链；内容和价格的演示属性清楚 |
| D5—D6 | AI 写真或口述故事至少一个真实生成 PoC，作品保存/分享模拟 | 真实 API/SDK 名称、延迟/费用/失败记录 |

## 9. 产品风险与设计检查

1. **公共隐私**：离开公共机不残留订单/人像/家庭信息；默认无私人记忆。不能无人授权自动接听或开启摄像头。
2. **声线/肖像**：有合法权利或明确授权才能定制真人声线、复刻真人形象；数字人身份和生成内容应有适用的清晰标识。
3. **信息与课程可信**：新闻有来源与时间，讨论时区分事实/观点；健康讲座需专业资质与广告审核。
4. **陪伴风险**：人格可以有温度，但不能冒充真人、以孤独诱导依赖或收费，不提供违规色情内容。
5. **AI 工具安全**：限制可调用操作和订单权限，外部动作可回看且由人确认；金额、商品、商家不可无依据生成。
6. **视频商业化**：短剧必须正版授权，营销明确标识、收费透明；不复制高压充值或误导性自动续费。
7. **演示真实性**：所有 Mock/预生成/真实推理及交易状态分清；无权宣称 SDK、联网支付或硬件功能已验收。
8. **数据权益**：个人记忆、作品可查看、导出、删除；内容二次使用必须取得相应授权。

## 10. 下一轮需要确认的设计问题（不影响启动信息架构）

1. **真实样机**：屏幕尺寸/分辨率、竖横屏、安卓版本、摄像头与麦克风、网络和音频输出能力。
2. **公共/个人身份**：是否一台设备允许多账户切换，机构设备如何锁定公共或个人模式。
3. **合法短剧/课程供给**：内容授权、播放器技术、成本与广告形态。
4. **首个 AI PoC**：写真、口述故事或数字人课程，哪一个能优先获得可用 API、素材和硬件。
5. **商家商品与权益样本**：2—3 个真实可被演示的商品/活动/服务，是否允许模拟订单。
6. **数字人供应商**：实时音视频、预生成课程、角色控制、成本和敏感内容处理方案。
7. **公共场景服务质量**：自助使用时的字体/音量/耳机/隐私及工作人员协助方式。
8. **家庭关系**：老人主动分享作品与子女代付的身份/授权界面。
