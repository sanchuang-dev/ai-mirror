## 1. 一句话定义

**见趣是一款以个人长期使用为主的大型 Android 平板式 AI 生活娱乐与服务终端。** 通过免费内容形成日常使用习惯，通过 AI 伙伴、创作、课程和熟人关系增加价值，通过自有商城、会员、透明广告与第三方服务实现商业承接。

不是养老院内部管理系统、放大的微信小程序、只会聊天的 AI 客服，也不是只供展厅围观的数字人设备。

**产品原则：内容让人停留，兴趣和熟人让人回来，AI 帮人做事，交易和服务必须由本人确认。**

## 2. 用户、设备与部署模式

| 对象 | 核心任务 | 权限边界 |
| --- | --- | --- |
| 个人用户（以中老年人群为重点，不排除其他年龄） | 看剧续播、娱乐学习、AI 趣玩、参加活动、购物、管理作品 | 拥有本人作品、偏好、订单及隐私控制权 |
| 子女与亲友 | 接收本人主动分享的作品、互动或代付 | 付费不等于读取私人聊天、长期记忆或未分享作品 |
| 商家、场地方、服务商 | 提供商品、课程、活动、履约 | 平台审核与治理；不访问私人 AI 记忆 |
| 平台运营 | 内容、网格、商家、会员与权益运营 | 不设任意查看私人会话的后台权限 |

**[已确认] 两种部署模式：**

- **个人专用设备**：有独立平台账户、个人内容与历史、AI 伙伴及经授权的分层记忆。AI 不主动闲聊，可由点击或用户开启的语音方式唤起。
- **公共服务设备**：默认游客，显示公共活动、福利、内容和通用服务 AI；不得进入私人人格、记忆和订单。涉及身份、支付或保存成果时，未来由自有 H5/账户承接。结束体验必须清理本次访客临时状态。

模式由设备部署决定，不以“机构购买”直接推断为公共模式。硬件尺寸、屏幕方向、Android/WebView 能力及外设仍待样机验证。

## 3. 功能版图与信息架构

八个功能域**不等于八个一级导航按钮**。用户面对的是内容和任务入口，AI 是可主动唤起的横向服务能力。

| 功能域 | 主要能力 | 典型页面/入口 |
| --- | --- | --- |
| 内容娱乐 | 免费短剧、频道、详情、分集、播放、收藏、续播 | H01 / V01 / V02 |
| AI 伙伴 | 通用问答、商品/活动辅助、私人角色、可控声线与记忆 | A01 / P02 |
| AI 趣玩 | 选主题、素材授权、预览、作品结果、私密保存与主动分享 | C01 / C02 |
| 本地生活 | 网格活动、福利、详情、报名确认、手机接力概念 | L01 / L02 |
| 自有商城 | 商品、入驻店铺、详情、购物车、订单预览 | M01 / M02 |
| 课程与数字人 | 课程内容、讲师/声线选择、示例互动 | E01 |
| 老友与亲情 | 熟人互动、作品展示、指定对象主动分享 | R01 与作品/个人空间关联 |
| 个人空间 | 作品、历史、收藏、订单、会员、偏好、隐私 | P01 / P02 |

**主要导航提案**：首页、看节目、AI 趣玩、本地生活、商城；“我的”和 AI 伙伴为常驻入口。此结构来自信息架构 V0.1，**不冒充产品负责人对最终导航逐项签收**。

公共设备从 **G00** 进入；**X01** 提供结束体验、确认/取消和模拟超时后的会话清理。

## 4. 五条核心体验链

1. **内容留存**：首页 → 节目目录 → 详情/选集 → 播放/收藏/续播 → 用户主动进入相关服务。不得以强制广告或虚假版权内容打断。
2. **AI 辅助购物**：主动唤起 AI → 查找/比较平台商品 → 打开同一商品详情 → 购物车 → 订单预览 → 本人确认。S1 只演示，不产生真实付款。
3. **活动与福利**：公共/个人入口 → 活动目录 → 详情 → 大屏确认或手机 H5 接力概念 → 明示模拟结果 → 公共会话结束清理。
4. **AI 趣玩与分享**：选主题 → 素材授权/取消 → 示例生成结果 → 默认私密 → 指定分享对象 → 二次确认；无真实生成时明确标注“预生成示例”。
5. **数字人课程**：进入课程 → 选讲师/声线 → 观看/暂停/简单提问演示 → 返回。角色表现不应篡改课程事实，真实数字人能力另做 PoC。

**跨链规则**：可触达的页面必须有明确返回/取消/失败路径；AI 不能代替用户确认外部动作；模拟成功不能包装成真实履约。

## 5. S1 / S2 / S3：能力与交付边界

| 深度 | 定义 | 当前判断 |
| --- | --- | --- |
| **S1 可操作原型** | 真实可点击页面与状态，允许明确标注的 Mock 数据、预生成素材及模拟结果 | **计划内实施卡已完成并合并 `dev`；整体产品/视觉验收仍待负责人签收** |
| **S2 真实 AI PoC** | 实际模型或 SDK 调用、输入输出、失败、延迟和成本证据 | **不得因 S1 页面可点击而宣称完成** |
| **S3 真实业务接入** | 授权内容、账户、商家、库存、订单/支付、报名核销与可验证回执 | **未因 S1 完成而成立** |

### S1 已落地的代表性范围

- 个人首页、内容目录与节目详情/续播示例；
- AI 趣玩输入/授权与结果/分享演示；
- 本地活动目录、详情、报名与公共手机接力概念；
- 商城、商品与订单确认演示；
- 个人空间与公共模式；
- 两种视觉主题的共享结构；
- **X01 公共会话结束与清理**：顶栏入口、确认/取消、模拟超时、返回 G00 并重建干净的访客页面状态。

X01 证据见 [PR #62](https://github.com/sanchuang-dev/ai-mirror/pull/62) 与 [验收证据](../engineering/evidence/x01-session-end/README.md)。该 PR 的独立验证通过；**不代表真机级清理已实现**。

### 明确未实现或未确认

- 真实 Android/WebView 系统缓存清理、设备级摄像头/麦克风复位、真实自动空闲计时器；
- 真实 AI 生成、实时数字人、长期记忆服务与可用性/成本 PoC；
- 真实短剧版权播放、真实商城支付、库存、退款、活动核销、身份扫码接力；
- 多账户切换、设备适配、横竖屏与触控实机验收；
- 商业合作方、商品、课程、人物形象与素材的正式授权；
- 线上留存、转化和交易效果。**S1 原型不证明真实商业指标。**

## 6. 视觉与交互设计合同

[DESIGN.md](../../design.md) 是视觉规范的主来源：

- A **日光客厅**：明亮、暖橙、杂志式内容呈现；
- B **暖夜剧场**：深色、暖金、海报与沉浸式内容呈现；
- **一套页面结构和交互，两套主题变量**；不为 A/B 各造一套业务页面；
- 主题是用户选择的外观，不按看剧/购物自动切换；
- 优先内容、可读性、触控和真实的任务完成，不做管理后台式卡片堆砌；
- 不把旧原型调试球、低保真草图或原始 OpenDesign 双 DOM 直接视作最终产品行为。

页面级验收顺序：**行为闭环 → 视觉继承 → A/B 一致 → 触控/设备适配 → 模拟内容真实性**。

## 7. 安全、隐私与商业红线

1. **私人数据属于本人**；亲友代付或机构采购不获得私人记忆访问权。
2. 公共模式不加载私人角色与历史；访客临时数据有结束与清理路径。
3. 分享、报名、下单、支付等对外动作必须由用户明确确认。
4. AI 的虚构 RP 记忆不得写入真实人生档案；不得借私密记忆进行隐性营销。
5. 免费内容、广告、赞助、示例价格、预生成素材和真实接口结果必须清楚区分。
6. 平台商城承接自有交易，商家入驻并负责授权范围内履约；不把外链跳转冒充平台交易。
7. 真实肖像、声音、影视、课程、健康信息与专业服务必须满足授权、资质和适用合规要求。

- 真实 Android 样机参数、公共模式部署和隐私清理责任边界；
