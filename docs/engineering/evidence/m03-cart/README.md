### 边界（按 Issue #17 与页面优先施工口径收口）

- **只模拟，不成交**：确认后只出现「模拟回执（演示，不是真实订单）」，状态固定为「未支付 · 未发货 · 未生成真实订单」，不显示已支付 / 已发货，也不是订单凭证。
- **取消不产生订单**：取消确认、查看失败示例、清空购物车都只改变页面状态；清空时同时移除购物车条目与订单预览 DOM，避免私人收货示例留在隐藏区域。
- **公共终端隔离**：`cart` 不在公共设备允许路由内；即便直接调用渲染，公共模式也只显示拦截说明，不出现示例地址、手机号或确认入口。
- **无货拦截**：礼盒装是显式「无货示例」，不能进入购物车或订单确认；数量变化不会恢复普通金额。购物车解析层也会重新校验当前规格，避免陈旧条目绕过。
- **数据诚实**：商品、店铺、价格、收货人、手机号、地址、优惠、回执编号均为虚构示例；没有真实账号、地址、库存、支付、物流或商家协议。
- **架构克制**：沿用现有 Vanilla JS / ESM、共享场景壳与 OpenDesign A/B Token，只增加一个轻量购物车路由和页面；未引入 React/Vite/Tailwind/Router，也未重构全局 Store / 缓存生命周期。

## 复现命令

```bash
npm ci --no-audit --no-fund
npm run check      # ESLint + Prettier + tsc(checkJs,strict) + node --check + node --test
npm run preview    # http://127.0.0.1:4173/
```

浏览器交互与截图经一次性 ChromeDriver（WebDriver）脚本驱动（按 browser-verification 约束**不入库**）：
`?dir=a` 打开 → 顶栏「商城」→ 打开「上臂式电子血压计」→ 数量 +1 →「加入购物车（示例）」→ 购物车数量减到 1（¥199 + ¥12 = ¥211）再加回 2（¥398、示例包邮）→ 查看订单信息 → 勾选本人确认 →「确认模拟提交（不会真实成交）」→ 切 B 主题 →「查看模拟失败示例」→「取消确认」→「清空购物车（示例）」→ 回 A → 打开同一商品 → 切「礼盒装」（无货示例）→ 点已停用的数量 + → 公共设备 `?device=public` 启动。

## 结果

- **质量门禁**：`npm ci --no-audit --no-fund && npm run check` 真实执行、退出码 0；Node 测试器 **138/138** 通过（含新增 M03 测试，未删除原有测试）。
- **验收 1（数量 / 运费 / 合计联动）**：购物车数量 1 时 `商品小计 ¥199`、`示例运费 ¥12`、`示例合计 ¥211`，提示「再买 ¥100（示例）可享包邮」；数量 2 时 `小计 ¥398`、`运费 ¥0（示例包邮）`、`合计 ¥398`。购物车行、订单预览和提示由同一份计算同步更新。
- **验收 2（本人确认 / 取消 / 模拟结果）**：确认按钮初始 `disabled=true`；勾选「本人确认」后才可用，点击后出现演示回执，含 `DEMO-M03-BLOOD-PRESSURE`、`未支付 · 未发货 · 未生成真实订单`、`不是订单凭证`，且回执文本不含「已支付 / 已发货」。取消后回执隐藏、确认状态清空，购物车保留但没有任何订单；「查看模拟失败示例」显示未生成订单 / 未扣款 / 未发货的显式失败态。
- **验收 3（公共终端隔离）**：单元 / 集成测试中公共设备 `show('cart')` 返回 `public`，公共壳内无购物车场景；直接以公共模式渲染购物车只出现「公共终端不展示购物车与收货信息」，DOM 中无示例地址、手机号与确认入口。浏览器 `?device=public` 启动为 G00 公共首页，`hasCartScene=false`。
- **验收 4（无货 / P3 回归）**：礼盒装下 `addDisabled=true`、`previewDisabled=true`，数量 + 为禁用；点击后金额区保持「无货示例状态：不提供加入购物车或订单合计；数量控件已停用」，不出现普通合计；购物车解析层对无货规格返回 `out-of-stock`、`totals=null`。
- **验收 5（A/B 与返回路径）**：购物车页在 A/B 主题下结构与金额完全一致，`sameDom=true`（切主题不重建页面）；两主题 `overflowX=false`；购物车「返回商品详情」回到同一 `product:blood-pressure`，商品详情再返回购物车。无 JS 错误：`errors=[]`。
- **空车 / 清空**：清空后购物车条目、订单预览与回执 DOM 一并移除，页面显示空车说明与「没有生成订单，也没有发起支付」，返回去向改为商品列表。

## 未覆盖 / 验证缺口

- 浏览器截图**不能**替代真实 Android 大屏 / WebView 触摸、对比度与读屏器实机验收（`design.md` §7）；本轮只截横屏 1600×900。
- 交互证据来自一次性 WebDriver 驱动脚本，未入库为可重复执行的浏览器测试；`npm test` 覆盖的是 Fake DOM 层的结构与状态断言。
- 公共设备直接进入购物车路由的拦截由单元 / 集成测试覆盖；浏览器本轮验证的是公共启动页与无购物车场景，因为应用未暴露可直接跳转的路由入口。
- 购物车只在当前页面会话内存在，刷新即清空；未实现跨设备购物车、账号地址、真实库存、优惠计算、支付、物流或商家履约。
- 「模拟提交失败」是显式演示状态，不代表真实服务端失败，也不持久化失败记录。
- 字体为本环境 Noto Sans/Serif CJK SC，与目标设备实际字体（苹方 / 宋体）可能有细微差异。
- 合并、验收、关闭 Issue、环境晋级与下张卡派工均需维护者另行授权。
